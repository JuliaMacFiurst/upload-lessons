# Регламент Использования MCP-Инструментов (MCP Policy)

> **СТАТУС ДОКУМЕНТА**: `POLICY` / `IMPLEMENTATION`

Документ определяет четкое разграничение между техническими возможностями инструментов (**Technical Capabilities**) и продуктовыми правилами проекта (**Project Policy**).

---

## ⚠️ Важное Различие: Capabilities vs Policy

> **Многие MCP-инструменты ТЕХНИЧЕСКИ УМЕЮТ выполнять изменяющие операции** (например, Supabase MCP технически имеет capability выполнять `INSERT/UPDATE/DELETE/DDL`, а инструменты работы с файлами умеют редактировать код).
> 
> Однако **ПОЛИТИКА ПРОЕКТА (`POLICY`) КАТЕГОРИЧЕСКИ ЗАПРЕЩАЕТ** использовать изменяющие технические возможности без прямого, явного подтверждения пользователя! [`POLICY`]

---

## 1. Реестр MCP-серверов и Полномочия

### A. Supabase MCP (`supabase`)
- **Technical Capabilities**: Выполнение произвольных SQL-запросов, просмотр таблиц, миграций и документации. [`IMPLEMENTATION`]
- **Project Policy (`POLICY`)**:
  - Использовать **СТРОГО В РЕЖИМЕ ЧТЕНИЯ (`SELECT`)**. [`POLICY`]
  - Запрещены изменяющие SQL-запросы (`INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `ALTER`, `DROP`). [`POLICY`]
  - Запрещено выполнение миграций (`apply_migration`). [`POLICY`]

---

### B. Chrome DevTools MCP (`chrome-devtools`)
- **Technical Capabilities**: Управление браузером, инспекция DOM, снятие скриншотов, выполнение JS-скриптов. [`IMPLEMENTATION`]
- **Project Policy (`POLICY`)**:
  - Разрешена отладка локальных страниц проекта (`localhost`). [`POLICY`]
  - **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** использовать DevTools для чтения личных вкладок пользователя, электронной почты, банковских страниц и сторонних сессий. [`POLICY`]

---

### C. Context7 MCP (`context7`)
- **Technical Capabilities**: Поиск документации по сторонним библиотекам. [`IMPLEMENTATION`]
- **Project Policy (`POLICY`)**: Использовать для уточнения синтаксиса библиотек. Справка Context7 **не является источником истины для бизнес-логики проекта**. [`POLICY`]

---

### D. GitHub Connector MCP (`github`)
- **Technical Capabilities**: Просмотр репозиториев, коммитов, пулл-реквестов, создание issue и коммитов. [`IMPLEMENTATION`]
- **Project Policy (`POLICY`)**:
  - Разрешен просмотр истории коммитов и описаний PR для анализа контекста. [`POLICY`]
  - **Запрещено автоматически создавать коммиты, ветки или пулл-реквесты** без явного поручения пользователя. [`POLICY`]

---

### E. Локальный доступ к файловой системе
- **Project Policy (`POLICY`)**:
  - Чтение и редактирование файлов проекта в пределах стандартных рабочих директорий (`upload-lessons/`, `capybara_tales/`). [`POLICY`]
  - **Запрещено читать и выводить** секреты, пароли, ключи API из файлов `.env`, `.env.local` и `.git-credentials`. [`POLICY`]
