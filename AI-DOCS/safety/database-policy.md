# Политический Регламент Работы с Базой Данных (Database Safety Policy)

> **СТАТУС ДОКУМЕНТА**: `POLICY`
> **ПРЕДНАЗНАЧЕНИЕ**: Данный документ запечатывает правила безопасности для AI-агентов при взаимодействии с базой данных Supabase. Это редакционный и технологический регламент AI, а не ограничение физических возможностей PostgreSQL.

---

## 1. Режим Read-Only по умолчанию

1. Любые операции AI-агентов с production-базой данных Supabase осуществляются **строго в режиме чтения (Read-Only)**. [POLICY]
2. Выполнение запросов `SELECT` через Supabase MCP или серверные контроллеры разрешено для анализа схем, подсчета метрик и проверки фактологии. [POLICY]

---

## 2. Категорически запрещённые операции

Без отдельного, прямого и явного поручения пользователя AI-агенту **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО**: [POLICY]

- Выполнять SQL-запросы `INSERT`, `UPDATE`, `DELETE`, `TRUNCATE`, `UPSERT`. [POLICY]
- Выполнять операторы DDL (`CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, `CREATE INDEX`). [POLICY]
- Запускать или применять миграции PostgreSQL (`apply_migration`). [POLICY]
- Автоматически удалять сиротские строки (orphan rows), такие как невязанные записи в `map_stories`. [POLICY]
- Перезаписывать существующий контент без явного указания целевых ID. [POLICY]

---

## 3. Безопасная схема создания и изменения контента

При необходимости внесения или изменения данных AI-агент обязан придерживаться следующего регламента: [POLICY]

```text
[1. Исследование & SELECT] ➔ [2. Генерация Draft / JSON] ➔ [3. Показ пользователю] ➔ [4. Явное одобрение] ➔ [5. Вызов Admin API]
```

1. **Генерация черновика (Draft)**: AI-агент подготавливает готовый результат в виде структурированного валидного JSON или Markdown-черновика. [POLICY]
2. **Согласование**: Черновик передается пользователю на проверку. [POLICY]
3. **Запись через Admin API**: Изменения вносятся **только через существующие валидируемые эндпоинты административной панели** (`pages/api/admin/...`), использующие сессию администратора и серверную валидацию. Прямой SQL-insert в базу запрещен. [POLICY]

---

## 4. Правила работы с пакетами и статусами

- **Тестовые партии**: Любая массовая операция импорта или обновления сначала выполняется на малой тестовой партии из 5–10 элементов. [POLICY]
- **Статус `is_approved`**: AI-агент не имеет права автоматически устанавливать `is_approved = true` для сгенерированного им текста. Автоматически сгенерированный контент всегда получает `is_approved = false` и `auto_generated = true` до ручной редакторской проверки. [POLICY]
- **Запрет "исправления" `target_id`**: Запрещено модифицировать, "исправлять" или нормализовать значения `target_id`, даже если они содержат диакритику, пробелы или кажутся опечатками. [POLICY]
- **План отката при удалении**: Любая операция удаления контента требует предварительного формирования плана отката (создание бекап-копии удаляемых строк в JSON). [POLICY]
