# Техническая и Редакторская Спецификация: Map Content Writer

> **СТАТУС ДОКУМЕНТА**: `SPECIFICATION` / `POLICY` / `DESIGN`

---

## 1. Разделение Ответственности и Получение Объектов

Навык **не принимает самостоятельных решений о выборе объектов**. На вход навыку всегда передается целевой список объектов, сформированный внешним процессом (оркестратором, batch-runner или человеком). Настоящая спецификация является предметной реализацией стандартов [`skill-pipeline-standard.md`](../skill-pipeline-standard.md) и [`skill-validation-standard.md`](../skill-validation-standard.md). [`POLICY`]

Подбор незаполненных объектов из базы данных выполняется отдельным внешним компонентом. Ниже приведен SQL-запрос, используемый внешним оркестратором в качестве эталонного ориентира: [`DESIGN`]

```sql
-- Reference Query для внешнего оркестратора (НЕ обязанность навыка)
SELECT mt.map_type, mt.target_id, mt.title_ru, mt.title_en, mt.title_he
FROM map_targets mt
LEFT JOIN map_stories ms 
  ON ms.type = mt.map_type 
 AND ms.target_id = mt.target_id 
 AND ms.language = 'ru'
WHERE ms.id IS NULL
  AND mt.map_type = $1
ORDER BY mt.id ASC
LIMIT $2;
```
[`IMPLEMENTATION`]

## 2. Работа с Пакетными Запросами

- **Масштабируемость пагинации**: Внешний оркестратор использует курсор продолжения (`continuation cursor` / `starting_after_id`) для выборки следующих партий. Навык принимает готовый список объектов без использования поисковых курсоров. [`POLICY`]
- **Однородность пилотных партий**: На этапе пилотирования партия формируется из объектов одного `map_type` для сохранения фокусировки навыка. [`POLICY`]

---

## 3. Заголовки и Immutable Target Contract (10 Запретов)

1. **`title_ru`**: Главный источник человекочитаемого названия объекта для использования в русском тексте. [`POLICY`]
2. **`title_en`**: Поисковый якорь для фактчекинга и поиска в англоязычных энциклопедиях. [`POLICY`]
3. **`title_he`**: Поле `title_he` принимается навыком, но не используется. [`POLICY`]
4. **Служебный статус `target_id`**: Поле `target_id` помещается в **Protected Immutable Reference** и сохраняется посимвольно. Запрещены: trim, изменение регистра, любых пробелов, тире, кавычек, диакритики, нормализация Unicode, транслитерация, slugify и сборка из полей заголовков. [`POLICY`]

*Сравнение `target_id` с базой `map_targets` и `map_stories` производится только посимвольным exact равенством `=`. Использование `ILIKE`, prefix или fuzzy-matching запрещено.* [`POLICY`]

---

## 4. Исследование Фактов (Research Dossier) и Принцип «Не уверен — не пиши»

- **Досье Исследования**: Исследователь **не пишет текст**, а формирует досье объекта `VerifiedFactsDossier` из 4 блоков: `confirmed_facts[]`, `rejected_facts[]`, `uncertainties[]`, `source_summary[]`. [`POLICY`]
- **Fail-Fast / Принцип «Не уверен — не пиши»**: Если факт не удается подтвердить минимум по 2 независимым источникам или объект неоднозначен ➔ `STOP-RESEARCH-01` / `STOP-RESEARCH-02` (объект отбрасывается). [`POLICY`]

---

## 5. Смысловой Фокус (Semantic Focus)

> ⭐️ **СЕРДЦЕ НАВЫКА**: Главная тема текста определяется **исключительно** значением `map_type`.

| `map_type` | Главная тема текста (Semantic Focus) |
|---|---|
| `country` | Страна, её географический образ, столица и быт |
| `food` | Кухня, блюда, ингредиенты, физика и химия приготовления |
| `culture` | Традиции, праздники, ремёсла, одежда и музыка |
| `river` | Гидрография, исток, устье, течения и речная экосистема |
| `weather` | Климат, осадковый режим, ветра и физика атмосферы |
| `animal` | Природный биом и адаптированные животные этой экосистемы |
| `physic` | Физико-географический объект (остров, горы, пустыня) |
| `sea` | Водный объект (море, пролив, залив) и его режим |
| `flag` | Государство через призму символики и истории флага |

> 🚨 **Запрет Авто-Мутации `map_type`**: Редактор `Map-Type Review` не имеет права самостоятельно менять `map_type`. При несоответствии ➔ `STOP-TYPE-02` (STOP). [`POLICY`]

## 6. Редакторский Формат и Правила Генерации

- **Объем**: Жёсткий диапазон **80–140 слов** (целевой ориентир 90–130 слов / 6–8 связных предложений). [`POLICY`]
- **Эмодзи**: Допускается максимум **1 тематический эмодзи только в 1-м предложении** (не обязательно). В остальных предложениях эмодзи категорически запрещены. [`POLICY`]
- **Тематический Hook**: Первый зачин должен сразу вводить предмет конкретного объекта. [`POLICY`]
- **Открытый CTA**: Финальный вопрос обязан быть открытым мыслительным вопросом (*«Как ты думаешь...»*, *«Почему...»*). [`POLICY`]
- **Отсутствие Markdown**: Никаких ссылок, разметки или сносок внутри поля `"content"`. [`POLICY`]

## 7. Канонический Конвейер Ответственности (10 Стадий)

Навык выполняет 10 канонических стадий конвейера ([`workflow.md`](workflow.md)): [`DESIGN`]

1. `1. Metadata Lock`
2. `2. Production Context`
3. `3. Research` (`VerifiedFactsDossier`)
4. `4. Story Outline` («Идея ➔ Факты на идею»)
5. `5. Writer` (Текст 80–140 слов, макс 1 эмодзи в 1-м предложении)
6. `6. Map-Type Review` (`Semantic Focus`, без авто-мутации `map_type`)
7. `7. Fact Check` (Пословный аудит атомарных утверждений по досье)
8. `8. Kids Editor` (Тон 6–10 лет, тематичный Hook и открытый CTA)
9. `9. Definition of Done` (Quality Gate — бинарный PASS/FAIL, без переписывания контента!)
10. `10. Candidate Assembly` (Сборка вывода)

---

## 8. Канонические Критерии Готовности (Definition of Done — 11 Критериев)

Навык признает результат готовым **только при выполнении всех 11 условий**: [`POLICY`]

1. [ ] Объект подтвержденно существует в `map_targets` (`exact SELECT`).
2. [ ] Точная RU-история `map_stories` (`language = 'ru'`) в базе отсутствует (`exact SELECT`).
3. [ ] Поле `target_id` сохранено посимвольно согласно `Protected Immutable Reference`.
4. [ ] Поле `map_type` сохранено и входит в allowlist 9 семантических типов.
5. [ ] Выходной JSON полностью валиден.
6. [ ] Выходной объект в режиме импорта содержит ровно три ключа (`map_type`, `target_id`, `content`).
7. [ ] Текст строго соответствует `Semantic Focus` своего типа карты.
8. [ ] Каждое атомарное фактическое утверждение подтверждено по досье `confirmed_facts[]`.
9. [ ] Hook уникален и относится именно к предмету данного объекта.
10. [ ] CTA является открытым мыслительным вопросом (*«Как ты думаешь...»*, *«Почему...»*).
11. [ ] Объем текста находится в диапазоне 80–140 слов (обычно 90–130), содержит не более 1 эмодзи в 1-м предложении, а production-СУБД не изменялась.

---

## 9. Формат Выходных Данных

Выходной результат возвращается в соответствии с режимом вывода ([`skill-contract.md`](skill-contract.md#4-output-contract-два-режима-вывода)): `Contract Test Report` (в режиме `IMPLEMENTED`/`VALIDATION`) или `Candidate for Review JSON` (в режиме `PILOT`+). [`POLICY`]
