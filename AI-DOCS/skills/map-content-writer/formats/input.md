# Спецификация Входного Формата (Input Format)

> **СТАТУС ДОКУМЕНТА**: `SPECIFICATION` / `POLICY`

---

## 1. Входной Контракт

Навык `Map Content Writer` получает **исключительно готовый массив объектов**, сформированный внешним Orchestrator, batch-runner'ом или человеком. [`POLICY`]

Навык **НЕ принимает самостоятельных решений о подборе следующих объектов**, не использует поисковые курсоры (`starting_after_id`), не выполняет запросы вида «выбери следующие 5» и не занимается формированием партий. Вся логика пагинации и выборки является ответственностью внешнего процесса (Orchestrator). [`POLICY`]

---

## 2. Формат Входного Массива

Каждый объект входного массива передается в следующей структуре: [`POLICY`]

```json
[
  {
    "map_type": "river",
    "target_id": "Moma",
    "title_ru": "Мома",
    "title_en": "Moma",
    "title_he": "מומה"
  }
]
```

---

## 3. Реестр Атрибутов Входа

| Атрибут | Тип | Обязательность | Описание |
|---|---|---|---|
| `map_type` | `string` | **Обязательно** | Один из 9 разрешенных типов СУБД из allowlist. |
| `target_id` | `string` | **Обязательно** | Точное значение `target_id` из таблицы `map_targets`. |
| `title_ru` | `string` | **Обязательно** | Официальное русское название объекта. |
| `title_en` | `string` | **Обязательно** | Английское название для фактчекинга и поиска. |
| `title_he` | `string` | Опционально | Ивритский заголовок (принимается, но навыком не используется). |
