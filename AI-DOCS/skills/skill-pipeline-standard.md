# Стандарт Конвейера Ответственности AI-Навыков (Skill Pipeline Standard)

> **СТАТУС ДОКУМЕНТА**: `POLICY` / `DESIGN`

Настоящий документ определяет **Универсальный Конвейер Ответственности (Responsibility Pipeline Standard)** для всех специализированных AI-навыков платформы «Сказки Капибары». На стандарт опираются все создаваемые навыки (`Map Content Writer`, `Multi-language Translator`, `Book Database Editor`, `Recipe Writer`, `Map Slide Image Curator` и др.). [`POLICY`]

---

## 1. Концепция Конвейера Ответственности

Вместо монолитных промптов все навыки системы проектируются как **детерминированный конвейер ролей**. Каждая роль конвейера имеет жестко зафиксированные входные и выходные артефакты, выполняет строго одну функцию и реализует механику немедленной остановки при сбое (**Fail-Fast**). [`POLICY`]

```text
Input (Входные данные)
  │
  ▼
1. Metadata Lock (Захват служебных идентификаторов)
  │
  ▼
2. Context (Загрузка ограничений проекта и исторических наблюдений)
  │
  ▼
3. Research (Исследование и сбор досье фактов) ──────────► НЕ УВЕРЕН / ОШИБКА? ➔ STOP
  │
  ▼
4. Outline (Проектирование главной идеи и каркаса)
  │
  ▼
5. Creator (Создание основного контента по каркасу)
  │
  ▼
6. Domain Review (Проверка предметной семантики) ────────► НЕ ТОТ ДОМЕН? ➔ STOP
  │
  ▼
7. Fact Review (Пословный фактологический аудит) ────────► ГАЛЛЮЦИНАЦИЯ? ➔ STOP
  │
  ▼
8. Audience Review (Проверка тональности для ЦА) ────────► ИНФАНТИЛИЗМ? ➔ STOP
  │
  ▼
9. Definition of Done (Quality Gate) ───────────────────► FAIL? ➔ STOP (No Rewrite!)
  │
  ▼
Output: Candidate for Review (Кандидат на проверку человеком)
```

---

## 2. Универсальные Роли и Правила Конвейера

1. **`Metadata Lock`**: Захватывает служебные ID в `Protected Immutable Reference`. Запрещает любые модификации ключей. [`POLICY`]
2. **`Context`**: Считывает проектные наблюдения (`STATE`) для исключения повторяющихся ошибок прошлого. [`POLICY`]
3. **`Research`**: Сбор структурированного досье. **Исследователь не создает контент**, а только собирает подтвержденные факты, помечает неопределенности и отвергает сомнительное. Принцип: *«Не уверен — не пиши (STOP)»*. [`POLICY`]
4. **`Outline`**: Формирование главной идеи и подбор 3–5 фактов, **работающих на эту идею**. [`POLICY`]
5. **`Creator`**: Генерация контента строго по подготовленному каркасу и досье фактов. [`POLICY`]
6. **`Domain Review`**: Проверка предметной темы. **Запрещено самостоятельно менять тему или домен** (например, с `food` на `culture`). При расхождении — **STOP**. [`POLICY`]
7. **`Fact Review`**: Сверка созданного контента с досье `Research`. [`POLICY`]
8. **`Audience Review`**: Шлифовка тональности под целевую аудиторию (6–10 лет). [`POLICY`]
9. **`Definition of Done`**: Детерминированный Quality Gate. **Quality Gate не изменяет содержимое контента. Он принимает исключительно бинарное решение: PASS или FAIL**. [`POLICY`]
10. **`Candidate for Review`**: Выходной результат возвращается для ручной проверки человеком. Автоматический импорт в production запрещен. [`POLICY`]
