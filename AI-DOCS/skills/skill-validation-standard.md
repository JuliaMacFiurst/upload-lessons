# Стандарт Валидации, Пилотирования и Допуска AI-Навыков (Skill Validation Standard)

> **СТАТУС ДОКУМЕНТА**: `SPECIFICATION` / `POLICY` / `DESIGN`  
> **ОБЯЗАТЕЛЬНЫЙ СТАНДАРТ**: Настоящий документ задает нормативный регламент проверки, пилотирования, версионирования и выдачи допусков для **всех AI-навыков** платформы «Сказки Капибары».

---

## 1. Главный Вопрос Стандарта

> **Главный вопрос стандарта**: *«Когда набор документов, спецификаций и исполняемых инструкций можно официально считать проверенным AI-навыком, которому разрешено выполнять реальные продуктовые задачи?»*

Настоящий стандарт исключает самовольное повышение статусов, гарантирует немедленную остановку при дефектах безопасности (**Fail-Fast**) и полностью разделяет качество генерации контента и техническое право записи в СУБД. [`POLICY`]

---

## 2. Официальные Статусы Жизненного Цикла Навыка

Каждый AI-навык системы находится строго в одном из 8 последовательных статусов жизненного цикла. Статусы `FAILED_VALIDATION`, `SUSPENDED`, `DEPRECATED` и `ARCHIVED` являются **боковыми состояниями**: [`POLICY`]

```text
[IDEA] ➔ [RESEARCH] ➔ [SPECIFICATION] ➔ [IMPLEMENTED] ➔ [VALIDATION] ──(PASS Gate 5)──► [PILOT] ➔ [LIMITED] ➔ [PRODUCTION_READY]
   │            │               │               │              │                           │         │                 │
   │            │               │               │              ├─► [FAILED_VALIDATION]     │         │                 │
   └────────────┴───────────────┴───────────────┴──────────────┴───────────────────────────┴─────────┴─────────────────┴──► [SUSPENDED]
   │                                                                                                                             │
   └─────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┴──► [DEPRECATED] ➔ [ARCHIVED]
```

### Основная последовательная линия:

#### 1. `IDEA`
- **Описание**: Потребность сформулирована, но исследования, контракта и спецификации нет.
- **Разрешено**: Обсуждение концепции.
- **Запрещено**: Создание кода, `SKILL.md`, запуск генерации или вызов MCP.

#### 2. `RESEARCH`
- **Описание**: Исследуются код, СУБД, workflow и реальные примеры production.
- **Разрешено**: Использование Supabase MCP строго в режиме `SELECT`, чтение кода и документации.
- **Запрещено**: Создание `SKILL.md`, запуск пилотов, вызов записывающих API.

#### 3. `SPECIFICATION`
- **Описание**: Подготовлен пакет документации и сформирован неизменяемый **Skill Contract** (см. Раздел 5).
- **Разрешено**: Анализ спецификации, рецензирование, статическая валидация контракта.
- **Запрещено**: Создание `SKILL.md`, исполнение кода, запуск промптов.

#### 4. `IMPLEMENTED`
- **Описание**: Создан исполняемый файл `SKILL.md` и сформирован обязательный файл `validation-record.md`.
- **Правило присутствия**: Навык в статусе `IMPLEMENTED` без созданного `validation-record.md` **КАТЕГОРИЧЕСКИ НЕ СУЩЕСТВУЕТ**. [`POLICY`]
- **Разрешено**: Статические тесты, проверка синтаксиса, прогон на локальных mocks (`dry-run`).
- **Запрещено**: Запуск пилота до прохождения `Gate 5`.

#### 5. `VALIDATION`
- **Описание**: Проводятся статические (Gate 3), адверсариальные (Gate 4) тесты и пред-пилотный аудит (Gate 5).
- **Разрешено**: Запуск промпт-тестов в режиме `dry-run` и проверка на `adversarial cases`.
- **Запрещено**: Запуск пилота до получения отметки `PASS` на Gate 5. При неудаче навык переходит в `FAILED_VALIDATION`.

#### 6. `PILOT`
- **Описание**: Навык прошёл `Gate 5` и выполняет тестовые задачи на реальных Read-Only данных. Результаты вывода имеют статус **Candidate** (`Candidate for Review`).
- **Разрешено**: Генерация кандидатов для ручной проверки человеком.
- **Запрещено**: Автоматический импорт или запись в СУБД.

#### 7. `LIMITED`
- **Описание**: Навык успешно прошёл `Gate 7` и допущен к ограниченным задачам со 100% ручной проверкой человеком.
- **Разрешено**: Генерация кандидатов под ручной контроль.
- **Запрещено**: Автоматическая пакетная выкатка.

#### 8. `PRODUCTION_READY`
- **Описание**: Навык достиг утвержденных показателей качества и допущен к выкатке в продакшн.
- **Разрешено**: Массовая подготовка кандидатов для редакционного импорта.
- **Запрещено**: Запись в СУБД без выданного `Mutation Grant`.

---

### Боковые состояния:

#### `FAILED_VALIDATION` (Не прошел валидацию)
- **Описание**: Боковое состояние. Навык открыт в коде, но заблокирован на этапе валидации (Gate 3, Gate 4 или Gate 5).
- **Вход**: Автоматически при решении `FAIL` на шлюзах Gate 3, 4 или 5.
- **Выход**: Возврат в `IMPLEMENTED` после исправления `SKILL.md` и повторной подачи на тесты.

#### `SUSPENDED` (Приостановлен)
- **Описание**: Боковое состояние. Навык временно заблокирован из-за дефекта безопасности (`S4`–`S5`), сбоя тестов или изменения СУБД/POLICY.
- **Вход**: Из любого активного статуса.
- **Выход**: Только через процедуру **Revalidation** (повторные Gates 3–8).

#### `DEPRECATED` (Устарел)
- **Описание**: Боковое состояние. Навык заменён новой версией или выведен из эксплуатации.
- **Переход в `ARCHIVED`**: По истечении срока хранения архивных данных согласно процедуре **Skill Retirement** (см. Раздел 13).

#### `ARCHIVED` (Архивирован)
- **Описание**: Финальное боковое состояние. Навык полностью запечатан, исполнение запрещено. Документы сохраняются только для исторической аудируемости и воспроизводимости прошлых загрегированных результатов.

## 4. Модель Независимых Допусков и Жизненный Цикл Mutation Grant

> 🚨 **ФУНДАМЕНТАЛЬНОЕ ПРАВИЛО**: **Качество генерации контента (`Content Capability`) и право записи в СУБД (`Mutation Capability`) — это две абсолютно независимые оси!** [`POLICY`]

### Жизненный Цикл Mutation Grant:
```text
[NO_WRITE] ➔ [REQUESTED] ➔ [UNDER_REVIEW] ──(Approved)──► [GRANTED]
                                 │                            │
                                 └──(Rejected)──► [NO_WRITE]   ├──► [SUSPENDED]
                                                              │
                                                              └──► [REVOKED]
```

1. **`NO_WRITE`**: Начальное состояние по умолчанию для всех навыков.
2. **`REQUESTED`**: Запрошен доступ на запись с указанием эндпоинтов и таблицы Scope.
3. **`UNDER_REVIEW`**: Проводится аудит безопасности записи (`write-validation track`).
4. **`GRANTED`**: Допуск выдан владельцем проекта с фиксацией даты, кем выдан и для каких эндпоинтов.
5. **`SUSPENDED`**: Временно заблокирован при ошибках записи или изменении API.
6. **`REVOKED`**: Допуск отзывается навсегда без снижения `Content Capability` навыка.

## 5. Контракт Навыка (Skill Contract)

Между этапами `SPECIFICATION` и `IMPLEMENTED` фиксируется **Skill Contract (Контракт Навыка)** — не зависящий от конкретной модели или реализаций нормативный документ: [`POLICY`]

```text
Specification ➔ [SKILL CONTRACT] ➔ Implementation (SKILL.md)
```

**Обязательные секции Skill Contract**:
1. `Input Schema`: Жесткая структура входных параметров.
2. `Output Schema & Lifecycle`: Пошаговый статус вывода (`Draft` ➔ `Candidate` ➔ `Approved`).
3. `Stop Conditions`: Жесткие триггеры отсечки (**Fail-Fast**).
4. `Allowed & Forbidden Tools`: Разрешенные и запрещенные MCP-инструменты.
5. `Responsibility Pipeline`: Роли и артефакты 10-этапного конвейера.
6. `Capabilities`: Разрешенные действия и ограничения.

## 7. Ворота Валидации (Validation Gates 0–8) и Административный Артефакт `owner-decision.md`

Для повышения статуса навык обязан последовательно пройти 9 шлюзов контроля: [`POLICY`]

```text
Gate 0: Doc Integrity ➔ Gate 1: Spec Completeness ➔ Gate 2: Implementation Fidelity ➔ Gate 3: Static Tests ➔
Gate 4: Adversarial Safety ➔ Gate 5: Pre-Pilot Independent Review ➔ Gate 6: Pilot Quality ➔
Gate 7: Post-Pilot Independent Evaluation ➔ Gate 8: Owner Release Decision
```

### 🎯 Детализация ответственности Gate 8 и Артефакт `owner-decision.md`:
> **🚨 ЗОНА ОТВЕТСТВЕННОСТИ GATE 8**: Gate 8 отвечает **ИСКЛЮЧИТЕЛЬНО на административный вопрос**:  
> *«Утверждает ли владелец проекта повышение Lifecycle Status навыка на основе доказательств, зафиксированных в Gates 0–7?»*  
> Gate 8 **НЕ перепроверяет качество текста** и НЕ перепроводит фактчекинг. Результат фиксируется в **обязательном административном артефакте `owner-decision.md`**. [`POLICY`]

#### Структура артефакта `owner-decision.md`:
- `Decision`: APPROVED / REJECTED / CONDITIONAL_APPROVAL
- `Target Status`: Проектируемый новый Lifecycle Status
- `Reason`: Краткое обоснование административного решения
- `Evidence`: Ссылки на сертифицированные протоколы Gates 0–7 и `validation-record.md`
- `Risk Accepted`: Перечень принятых рисков и допущений
- `Owner`: Имя/Роль лица, принявшего решение
- `Date`: Дата решения (YYYY-MM-DD)

## 8. Регрессионная Матрица Проверок (Regression Matrix)

При внесении изменений в файлы навыка повторная валидация выполняется строго по следующей матрице: [`POLICY`]

| Изменение / Триггер | Обязательные Шлюзы для Повторного Прохождения |
|---|---|
| Правки в `README.md` или опечатки в документации | **Gate 0** |
| Шлифовка формулировок промпта в `SKILL.md` | **Gates 3–4** |
| Изменение шагов `workflow` или ролей конвейера | **Gates 3–5** (Обязателен Pre-Pilot Review) |
| Изменение схемы JSON или контракта входов/выходов | **Gates 3–8** (Полный цикл ревалидации + `owner-decision.md`) |
| Изменение логики или эндпоинтов `Mutation Grant` | **Полный трек проверки записи + Gates 0–8** |
| Смена базовой AI-модели или среды выполнения | **Gates 3–8** (Полный цикл ревалидации) |

## 10. Метрики Оценки Навыка по Стадиям

### 1. Требования на стадии `PILOT` (Gate 6):
- **Срабатывание Stop Conditions**: Все stop conditions, представленные в утверждённом тестовом наборе, должны срабатывать корректно. Непроверенные условия перечисляются в `validation-record.md`. [`POLICY`]
- **Дефекты**: Любой дефект `S3` блокирует повышение; любой `S4` переводит навык в `SUSPENDED`.

### 2. Требования на стадии `PRODUCTION_READY`:
- **Фактологическая точность**: 0 известных фактологических ошибок в утверждённой выборке валидации (`validation sample`). [`POLICY`]
- **Критичность**: 0 дефектов классов `S3`–`S5`. [`POLICY`]
- **Валидность вывода**: 100% структурно валидных результатов JSON. [`POLICY`]
- **Защита ключей**: 100% сохранение защищенных идентификаторов (`target_id`). [`POLICY`]
- **Порог редакторских правок**: Индивидуальный порог допустимых стилистических правок задается паспортом конкретного навыка (например, меньше 5% правок для `Map Content Writer`). [`POLICY`]

## 11. Пополняемый Документ Проверок (`validation-record.md`)

Файл `validation-record.md` является **обязательным условием существования реализованного навыка**. Он создается одновременно с `SKILL.md` на этапе `IMPLEMENTED` и содержит: [`POLICY`]

- Название и Semantic Version навыка.
- Текущий `Lifecycle Status` и статус `Mutation Grant`.
- Проверенную версию `Skill Contract`.
- Журнал результатов по шлюзам Gates 0–8 с датами и именами рецензентов.
- Реестр обнаруженных дефектов `S0`–`S5` и статус их устранения.

## 12. Процедура Вывода из Эксплуатации (Skill Retirement Procedure)

Процедура вывода навыка из эксплуатации обеспечивает контролируемый переход в состояния `DEPRECATED` и `ARCHIVED`: [`POLICY`]

```text
[PRODUCTION_READY] ──(Депрекация)──► [DEPRECATED] ──(Архивация)──► [ARCHIVED]
```

1. **Переход в `DEPRECATED`**:
   - Навык помечается статусом `DEPRECATED` в `passport.md` и `validation-record.md`.
   - Поле `Mutation Capability` автоматически переводится в `NO_WRITE` / `REVOKED`.
   - Выполнение навыка в продуктовых процессах останавливается.
2. **Сохранение Исторической Аудируемости**:
   - Файлы `validation-record.md`, `validation-history.md` и `owner-decision.md` **сохраняются навечно**. Запрещено удалять историю проверок. [`POLICY`]
   - Файл `SKILL.md` сохраняется с пометкой `STATUS: DEPRECATED`.
3. **Воспроизводимость Исторических Результатов**:
   - Допускается запуск архивной версии `SKILL.md` **строго в режиме Read-Only Inspection (`dry_run: true`)** для проверки или воспроизведения прошлых результатов.
4. **Переход в `ARCHIVED`**:
   - По истечении срока поддержки архивированный навык перемещается в архивный реестр. Любой запуск заблокирован.
   - Восстановление навыка из `ARCHIVED` требует прохождения **Full Revalidation (Gates 0–8)** с новым релизным решением.
